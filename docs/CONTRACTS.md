# 相对稳定的规范（契约 v1）

## 数据证据

- `OBSERVED_LAYOUT_ONLY`：仅有盘面，`actions` 中交易字段必须全部 null，`wallet` 必须 null。
- `coord_source=INVENTORY_ONLY_NO_COORDS`：placements 必须 null，禁止默认 `(0,0,0)`。与“已知空盘面”的空数组不同。
- 完整 18 回合只是一个明确声明后才检查的 profile；短局不冒充 18 回合局，不补造缺回合。
- 所有物品 ID 均带来源命名空间。不同游戏版本、数据源和朝向编码不能直接混用。
- 累计金币不能充当当前钱包；盘面差分不能充当买卖日志；仅存活到 R18 的样本有幸存者偏差。

## 几何与收益

- 世界坐标 `[r,c]`，来源占格 `[dx,dy]`；原点由来源定义。
- 每个实例有唯一 instance_id；包与装备分层检查，同一层不允许重叠，装备需要被包格覆盖。
- 星位通道保持原名，不把星星、菱形、闪电等合成一个通用效果通道。
- `geometricLinks` 只输出几何交集，每个通道每个目标实例去重。不判断其类型是否符合真实效果，不计算战力。
- “能摆则摆”是用户策略约束，不等于纯战斗收益一定增加，更不是全局最优证明。

## 状态对账

- 推荐是预测，确认事件是事实，两者分离。已发生的合法交易入账不能再被路线权重否决。
- 状态带 game_id、revision；事件带 event_id、expected_revision。重复事件不重复入账，冲突 ID 报错。
- 游戏 ID 必须对应单次运行实例；跨新局不得复用同一 ID。持久化恢复需同时保存状态与事件账本。
- 外部事件确认失败、本地校验失败、状态冲突，均不得推进。确认后重新决策，不沿用“买一件就刷新”的陈旧续步。
- 本基础库不提供买卖自动化、游戏内存写入、游戏数值修改。

## 版本策略

当前发布版本 0.1.0：实验性独立实现，规则原则相对稳定，API 不承诺永久兼容。破坏性字段变化必须升级 schema_version，迁移须有测试。具体购买权重、路线倾向、效果公式和搜索参数不属于稳定契约。
